# Feature Match Overlay capability parity

The mapping from each legacy Feature Match Overlay construct to its Shared Graphics Foundation equivalent. It was settled on [issue #14](https://github.com/KeeprDigital/stream-keepr/issues/14) and lived only as a comment there; this file is the versioned copy the work that depends on it can cite.

Two issues consumed it. [#78](https://github.com/KeeprDigital/stream-keepr/issues/78) was the rewrite this mapping governs — moving Feature Match Overlay onto the shared compositor — and [#79](https://github.com/KeeprDigital/stream-keepr/issues/79) verified the result against this table item by item, recreated the built-in Feature Match Overlay Presets on the shared schema, and deleted the legacy widget, widget-group, and numeric z-index model. There is no converter and no migration: the database is wiped before ship, so this checklist is what stands in for one.

The verification is executable. `test/unit/shared/featureMatchOverlayCapabilityParity.test.ts` names one row per test and proves it against the recreated presets; a row that stops being true there is a capability the shared compositor can no longer express.

Per-side borders are deliberately dropped rather than carried forward. A Graphic Surface Style has one uniform outline, and an independently styled or animated edge is a Shape Graphic Item created from the rule preset. That is a capability decision, not an omission.

## The mapping

| Legacy construct                                                                   | Shared foundation equivalent                                                                    | Status                          |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------- |
| `widget` text with `{token}` template + per-token styles                           | Text Graphic Item with Graphic Text Template, host token binding catalogue, per-segment styling | Closed                          |
| `widget` image                                                                     | Media Graphic Item + Graphics Asset Library reference                                           | Closed                          |
| clock / player-life / game-wins widgets                                            | Shared context-gated Graphic Item Definitions                                                   | Closed                          |
| `widget-group` (row/column/canvas, gap, align, fixed/fill sizing, child overrides) | Graphic Group (carried forward per the settled vocabulary)                                      | Closed                          |
| Numeric `zIndex`                                                                   | Ordered back-to-front sibling lists                                                             | Closed                          |
| Per-side border flags                                                              | **Dropped from Surface Style** — compose with a thin Shape Graphic Item ("rule" preset)         | Closed                          |
| Per-corner radii                                                                   | Shape Geometry per-corner treatment                                                             | Closed                          |
| Box style (fill, gradient, opacity, glow, typography)                              | Graphic Surface Style + Text Graphic Item typography                                            | Closed (the last gap closed by #141) |
| Text overflow clip/ellipsis/shrink/visible                                         | Text Overflow Policy                                                                            | Closed                          |
| Frame, cutouts, source roles                                                       | Feature Match Overlay host layer (unchanged, host-specific)                                     | Closed                          |
| Built-in presets replacing whole layout                                            | Recreated as built-in Feature Match Layouts on the shared schema                                | Closed                          |

## How each row landed

- **`widget` text with `{token}` template** — a Text Graphic Item rendering a Graphic Text Template. The side moved out of the item and into the key: `{player1Name}` and `{player2Name}` are two entries of the Feature Match token binding catalogue the Host Contract carries, because a shared Text Graphic Item has no side. Three legacy token behaviours are deliberately not carried, and are recorded in `shared/featureMatchTokenCatalogue.ts`: `{spacer}` (layout expressed inside a string, now a Graphic Group's gap and justification), `{deckColors}` rendering colour pips rather than its own value, and the trimming of separators around a token that resolved empty.
- **`widget` image** — a Media Graphic Item pinning one exact Graphic Asset Revision. A Feature Match Overlay's silent-video references are indexed against a Chromium target, as a Broadcast Graphics Screen's are; the authored `videoTarget` the legacy model carried is gone, because both hosts are consumed as Chromium browser sources and neither offers a control that would say otherwise.
- **clock / player-life / game-wins** — shared Graphic Item Definitions gated on the Feature Match context the Host Contract declares. The definition palette offers them to Feature Match Overlay and withholds them from Broadcast Graphics.
- **`widget-group`** — a Graphic Group with row, column, and canvas arrangement, gap, padding, alignment, justification, fixed and weighted-fill main-axis sizing, optional clipping, and a local Graphic Surface Style default each direct child overrides with its own. The built-in presets set no such default, because what the legacy groups defaulted for their children was _typography_ — and typography belongs to each Text Graphic Item now, so every child states its own. Per-child `offsetX`/`offsetY`, `alignSelf`, `min`/`max` clamps, and a `content` sizing mode are not in the settled list and did not carry; `content` was rendered identically to `fixed` by the legacy model, so it expressed nothing.
- **Numeric `zIndex`** — Graphic Layer Order: the back-to-front list order of a composition's items and of a Graphic Group's children. Nothing authors a z-index, and the write schema rejects one.
- **Per-side border flags** — composed from rule-preset Shape Graphic Items. The `neon-feature-match` preset is the worked example: every panel that asked for a border on some sides and not others is a gradient bed plus one thin Shape Graphic Item per lit edge, and the upper rail — an otherwise invisible group with only a bottom border — is simply the Shape Graphic Item it always was. The glow follows the border, because it always did: the legacy box style emitted a shadow only for the sides it actually drew, so a partially bordered panel was lit on those edges alone, while the shared glow is a drop-shadow over the whole painted alpha and would light the unlit edges too. So each such panel's glow moves onto its edge rules, and a bed keeps a glow only where every side was bordered — the case a uniform outline states directly. The Frame and its Source Items keep per-side borders, because they are host capability the Host Contract leaves with the host.
- **Per-corner radii** — Shape Geometry configures each corner independently as square, rounded, or cut, and adds bounded left and right edge slants the legacy box style never had. It belongs to Shape Graphic Items, Graphic Groups, a Media Graphic Item's clip, and a Game Wins box — **not** to a Graphic Surface Style, so a rounded surface behind text is composed from a Shape Graphic Item bed beneath the Text, Clock, or Player Life Item. The Player Life pills in the built-in presets are that composition.
- **Box style** — a Graphic Surface Style: a Graphic Fill that is a solid colour or a linear gradient with two to four positioned stops, fill opacity, a uniform outline, and glow. Typography stays with the Text Graphic Item. The legacy gradient was an arbitrary CSS string; the `neon-feature-match` scoreboard used five stops and is recreated at the settled four.
- **Text overflow** — Text Overflow Policy: clip, ellipsis, or shrink to an author-set minimum and then ellipsis. The legacy `visible` option is deliberately dropped: text never renders with visible overflow beyond its authored bounds.
- **Frame, cutouts, source roles** — unchanged and host-owned. Source Items now have their own list on a Feature Match Layout rather than sharing the deleted widget list, and their `framingStyle` keeps exactly what a Source Item paints — background colour, background gradient, background opacity, per-side border, per-corner radii, and glow — with the widget-era typography, padding, and overflow removed. The gradient is still the raw CSS string it always was, as the Frame's own `gradient` is: the two-to-four-stop Graphic Fill is a rule the shared vocabulary makes for itself, and the two host-owned surfaces state one capability between them. `framingStyle` is named for the glossary's _source framing style_ rather than reusing "Surface Style", which is the shared vocabulary's own and a different set of properties.
- **Built-in presets** — `full-table`, `left-stacked-player-cams`, and `neon-feature-match` are recreated in full, item for item against what each replaced. A preset now initialises the whole layout: the Frame, the Source Items, and the shared item tree. Nothing is carried across on apply except the selected Feature Match Slot, which says what the Screen is pointing at rather than what it looks like.

## Structural consequences worth knowing

- **A Feature Match Layout is now `{ frame, sources, composition }`.** The Frame and the Source Items are host-owned; `composition` is one `BroadcastGraphicConfig` holding the shared Graphic Item tree. It is required rather than optional, because there is no other place for a Graphic Item to live.
- **The composition always sits above the Frame and the Source Items.** The compositor is mounted as one layer, so Graphic Layer Order cannot interleave a shared Graphic Item beneath a host-owned Source Item. In practice a Source Item paints a bordered hole rather than content, so what changes is only whether a graphic covers that border.

## Closed gap: Graphics Asset Library fonts

One capability the legacy model had was left open when this table was first written, and is recorded here because the shape of what closed it is worth knowing.

A legacy box style's `font` could be either an application font id or an exact Graphics Asset Library font revision, and the Feature Match Overlay Display loaded that revision as a `FontFace` before rendering. The rewrite carried only the application registry across, so for a while neither host could reference a library font — the Feature Match Overlay had lost the capability and a Broadcast Graphic never had it. That was recorded as a **Shared Graphics Foundation gap, not a settled drop**, and owned by [#141](https://github.com/KeeprDigital/stream-keepr/issues/141) rather than by this paragraph. Spec [#60](https://github.com/KeeprDigital/stream-keepr/issues/60) promises library fonts for both hosts ("reference images, silent videos, and fonts from the shared Graphics Asset Library"), and the Template Package envelope already embedded them.

**#141 closed it, for both hosts at once**, which is why it was never something this parity contract could half-build for one. A `GraphicTypography` and a Graphic Placeholder Style now carry a Graphic Font Selection: an application font id, or one exact font Graphic Asset Revision. That reference is discovered by `graphicsAssetReferences` beside the Media Graphic Item ones, so it is revision-pinned, indexed against the Screen, resolved through the Screen Output Asset Capability, and embedded by a Template Package with no font-shaped exception anywhere in the path. The `FontFace` loading the legacy Display did is back as `useGraphicAssetFontFaces`, shared by both Displays; an output whose library fonts have not loaded stays hidden rather than flashing a fallback typeface on air.

One thing is deliberately narrower than "both hosts": a **Graphic Style Set** typography preset still references application fonts only, because a `.skstyle` package carries no asset bytes for a library font to resolve against on the far side of a transfer. That is a recorded decision rather than an omission — see `docs/adr/0001-graphic-style-sets-reference-application-fonts.md` and [#143](https://github.com/KeeprDigital/stream-keepr/issues/143).
